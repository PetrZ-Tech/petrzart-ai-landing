# AGENTS.md — правила работы с проектом petrzart-ai-landing

## О проекте

Это статический сайт-портфолио ИП Зимина Петра: AI-интеграция, автоматизация бизнес-процессов, n8n, Supabase, CRM, Telegram, API и MVP-проекты.

Сайт работает как статический HTML-сайт на nginx.

Основные файлы:
- index.html — главная страница
- cases.html — страница кейсов, если создана
- policy.html — политика обработки персональных данных
- Dockerfile — сборка Docker-образа на базе nginx:alpine
- background.jpg — фон первого экрана
- assets/ — изображения и ассеты

## Главные правила

1. Не переводить проект на React, Next.js, Vite или другой фреймворк.
2. Не добавлять сборщик, package.json и новые зависимости без прямого запроса.
3. Работать в рамках статического HTML/CSS/JS.
4. Сохранять текущий премиальный стиль сайта: темный фон, золотые акценты, аккуратные карточки, Playfair Display и Inter.
5. Не ломать адаптивность под мобильные устройства.
6. Не удалять policy.html.
7. Не менять webhook формы заявки без прямого запроса.

## Форма заявки

В index.html уже используется webhook:

https://n8n.petrzart.ru/webhook/ai-petrzart-lead-prod-final

Эту ссылку не менять без отдельного указания.

Если создаются новые страницы с формой заявки, нужно использовать такую же логику модального окна и отправки формы.

## Кейсы

Проекты в портфолио должны быть оформлены как витрина кейсов.

Живые демо могут быть отключены на сервере для экономии ресурсов, поэтому основные CTA должны вести на видео-демонстрации, а не на работающие деплои.

Для видео использовать внешние ссылки. Не добавлять видеофайлы в репозиторий.

Временные заглушки ссылок:
- [VIDEO_STROYUCHET_URL]
- [VIDEO_HOTEL_URL]
- [VIDEO_INTAKE_URL]

## Визуальный стиль кейсов

Обложки кейсов должны быть в едином стиле.

Если нет готовых изображений, делать CSS-обложки прямо в HTML/CSS:
- графитовый фон
- золотые акценты
- mockup-карточки
- название кейса
- короткое описание
- бейджи стека

Не генерировать изображения через внешние сервисы.

## Dockerfile

Если добавляется новая HTML-страница, ее нужно явно добавить в Dockerfile.

Например, для cases.html:

COPY cases.html /usr/share/nginx/html/cases.html

## Git

Перед изменениями полезно проверить:

git status

После изменений показать:
- список измененных файлов
- краткое описание изменений
- финальный git status

Не делать commit и push без отдельного запроса пользователя.

## Безопасность

Не выводить секреты, токены, ключи API и пароли.
Не добавлять секреты в HTML, README или другие файлы.
